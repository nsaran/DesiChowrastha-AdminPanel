# Working preferences

## Resume content rules
- Never invent numbers, team sizes, dollar figures, or outcomes. Use only what the user states. If a number is missing, ask or leave it out.
- Show team sizes in each role entry. Do not show headcount in the summary or the Leadership section.
- The summary's client list excludes Ericsson and Deloitte. They appear as employers.
- Add a skill only after the user confirms they have used it. Do not add data lake, governance, or BI items unless a role supports them.
- Remove wording or skills the user rejects.

## Communication style
- Short, plain answers. No filler, no closing recap, no hype.
- If an edit request is ambiguous, ask one concrete question with the likely options. Do not guess.
- Report what changed and what still needs the user's decision.

## Privacy
- Personal matters discussed in chat (legal, financial, family, estate) must not be written into steering or skill files or committed to this repo.
